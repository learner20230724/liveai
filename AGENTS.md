# LiveAI maintenance

- This is the independent MOSS Live workspace at `https://guihualab.cn/liveai/`, not TTYD Hub. Repository: `learner20230724/liveai` (public), branch `main`.
- Never commit or expose the MOSS key, passwords, cookies, user conversations or usage logs. The server key lives in `/etc/liveai/moss.key`; service statistics live in `/var/lib/liveai`. The owner explicitly authorized native direct-to-MOSS media: authenticated `/api/mobile/bootstrap` encrypts this credential to a device-generated RSA public key at runtime. Android stores it and an optionally remembered password with Android Keystore AES-GCM. Never expose plaintext to JS, public source, APK, OTA bundles, screenshots or logs. This exception does not authorize embedding credentials in other projects.
- Preserve existing Guihua Lab authentication. The isolated auth fixture used for browser QA must never be deployed or used to bypass production authentication.
- The existing auth service listens on port 4190, which Node's browser-compatible `fetch` rejects as `bad port`. Use the native HTTP auth adapter for this trusted server-to-server connection; do not move the shared service or disable port protections globally. Auth integration tests must include a fetch-blocked port, and releases must verify actual production login with the existing password, session validation, catalog access and logout.
- Public HTML and assets must accept external link navigation. Apply Origin/Fetch Metadata CSRF restrictions to APIs and retain the independent WebSocket checks. Entry verification must click a link from a different origin, including redirects; same-origin navigation and direct URL requests alone do not cover this case.
- Prioritize `moss-live-1.0`. Do not silently replace its protocol with OpenAI Realtime or classic chat completions. Use the official MOSS docs and verify actual upstream behavior.
- Paid capabilities stay disabled unless the user explicitly requests enabling them. Unknown models are not implicitly free. No automatic retry/fallback to paid models or automatic recharge.
- Verify actual playback completion before sending acknowledgements; preserve interruption accounting, media cleanup, origin checks and microphone/camera consent.
- `npm test` and `npm run build` validate code. `npm run deploy` builds, tests and publishes the server/static release via `liveai.service`; then verify HTTPS assets, anonymous API rejection and the main flow. Physical M153 testing and synthetic browser testing must be reported separately.
- Update the existing LiveAI navigation card and real screenshot in `/home/ubuntu/apps/guihua-lab/` when relevant, preserving unrelated work. Read its publishing guide before changing Caddy; change only the current actual configuration.
- Commit and push only relevant changes to this public repository after checks. Do not create an APK for a browser-only change.
- The user requested the Dayweave APK delivery pattern: independent native WebView shell plus full-bundle OTA, not a remote-URL-only wrapper. Preserve package `cn.guihualab.liveai`, signing identity in `android/release.json`, HTTPS origin and `/liveai/` storage paths. Secrets/signing files remain under `/etc/liveai`, never in public assets.
- Run `npm run deploy:web` for both website and APP OTA resources; never update only one. Channel `liveai-stable`, endpoint `/liveai/app-updates/`. Cold startup applies compatible integrity-checked bundles with health rollback; background return does not refresh drafts. Native changes require shell version increments and the same signature.
- APK builds: `npm run build:apk`; verified publication: `npm run publish:apk`. Prefer the permanent IP download at `http://42.192.115.30:8182/downloads/liveai/liveai-latest.apk`, with HTTPS fallback. Do not use the temporary file-share area for app hosting. See `docs/android.md` for permissions and validation limits.

- Android 2.x uses a microphone foreground service plus partial wake lock, native AudioRecord/AudioTrack, OkHttp WSS directly to the fixed MOSS Live endpoint, and foreground-only Camera2 snapshots. Activity pause/stop/destruction must not end an explicit call. Camera stops on leaving the foreground; microphone and playback continue until end or a reported system/network error. Do not silently revert native calls to the relay.
- Use communication-device routing for duplex Bluetooth/USB/wired headsets and display AudioRecord.getRoutedDevice(), not just the requested output device. Background and headphone lifecycle simulations are not M153 hardware tests. Preserve actual-playback-head acknowledgement semantics and audio-priority video backpressure.

- Simplifying the mobile UI must preserve in-APP access to image generation (both free models and sizes), vision upload, the separate free/locked paid catalog, local history/export, and conversation presets/custom instructions. Keep the five-tab navigation and native call state while switching tools; do not replace mobile features with an external-browser link. Web-layer changes publish by OTA without requiring a new APK.
