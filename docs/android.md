## 安装与使用

- 原生外壳 **2.0.0 / versionCode 3**，稳定包名 `cn.guihualab.liveai`，独立正式签名，与日序及其他 APP 可以同时安装。
- 最低 Android 8 / API 26，compile/target SDK 36。单个通用 APK，不含 ABI 专用 `.so`，兼容 ARM64 / `arm64-v8a`；面向 nubia M153，不需要拆分安装。
- 下载后在手机点击 APK，按系统提示允许该下载来源安装应用。首次打开沿用规划 Lab 共享密码解锁，可勾选「在本机加密记住密码」。密码与 MOSS 密钥均未内置到安装包。直接覆盖安装旧版，不要卸载，以保留记录。
- 点击「开始对话」后才申请麦克风权限，并按 Android 版本请求蓝牙／附近设备和通知权限；通话中开启摄像头时才申请相机权限。拒绝后可去系统设置 → LiveAI → 权限调整，再重试。
- 系统选图器用于视觉模型上传；不申请相册读取或全盘存储权限。对话文字导出使用系统文件保存窗口，图片原图使用外部 HTTPS 浏览器打开保存。
- APP 初版支持语音及摄像头。Android WebView 不支持现有网页使用的 `getDisplayMedia` 接口，APP 隐藏不可用的屏幕共享按钮，屏幕共享请使用电脑网页。未宣称已实现原生 MediaProjection。
- 明确开始通话后，由独立 microphone 类型前台服务持有原生录音、播放、直连 WebSocket 和局部唤醒锁。锁屏、切后台、返回桌面或移除页面任务不主动结束语音；通知栏可静音和结束。摄像头在离开前台时释放，返回后按需手动开启，不做锁屏拍摄。设置 → 锁屏通话 → 允许，可减少电池优化限制；厂商后台管控、自启设置、系统强制停止、权限撤销和断网仍可能中断，应用不能保证绕过这些系统限制。无来电推送或自动发起通话，必须先由用户在前台开始。
- 支持双指缩放，原生处理状态栏、刘海、导航栏及软键盘边距；返回键退到后台；已开始的语音通话独立于页面继续。页面重新打开时恢复当前通话状态。

## APP 内的完整工具（网页资源 2.1.0）

底部五个入口为「对话、图像、视觉、模型、记录」。图像工作室保留 SFT/Base 两种模型、比例选择、示例、生成预览和原图保存；视觉页面保留选图和提问；模型目录继续分免费／付费锁定，记录可查看导出。通话设置恢复日常对话、口语陪练、看见与理解和自定义提示词。视觉模型上游不可用时仍显示真实状态，不冒充已修复上游。

这些工具直接在 APP 内打开。切换页面保留生成中的任务、结果、选图与输入，并显示可返回／结束的直连通话条。工具请求仍通过经过认证的规划 Lab API；原生通话继续直连 MOSS。工具登录过期时可用本机记住的密码恢复，未记住时在 APP 内解锁。服务器中转统计不计入原生直连通话。

本次恢复仅变更网页层，2.0.0 外壳无需重装。结束当前通话后，彻底关闭并重新打开 APP，冷启动会获取 2.1.0 完整资源包。原生权限和服务保持原版本。

## 直连、耳机与本机资料

APP 2.x 的音频、摄像头 JPEG、上游转录和语音回复，经原生 OkHttp 直接连接 `wss://api.mosi.cn/v1/realtime?model=moss-live-1.0`。不会自动回落服务器媒体中转。网页工具与旧版 1.x APP 仍用服务器 WebSocket 中转；图像生成等网页工具也仍由服务器调用。原生直连会话不计入原有服务器中转统计。

首次配置或主动刷新时，原生代码登录本项目 HTTPS 接口，再向经过认证的 `/api/mobile/bootstrap` 提交临时 RSA-2048 公钥，取得 RSA-OAEP SHA-256 密文并在原生内存解密；设备私钥不上传。运行期 MOSS 凭据、可选记住的密码和新通话文字经 Android Keystore AES-GCM 加密保存。JS 仅获得配置是否就绪，不能读取这些密钥。配置成功后开始通话无需再次经过规划 Lab；删除配置或密钥轮换时需重新配置。公开源码、安装包和 OTA 包都没有真实密码、密钥或签名材料。APK 禁止云备份及设备迁移备份，本地记录导出需用户主动操作。

录音使用 `VOICE_COMMUNICATION`，Android 12+ 用 `setCommunicationDevice` 选择可双向通话的蓝牙／BLE、USB、有线耳机，旧系统使用 SCO。自动模式优先耳机，音频设备面板支持切换，并用 `AudioRecord.getRoutedDevice()` 显示真实输入及实际输出。音乐 A2DP 连接本身不代表耳机麦克风已可用；拒绝蓝牙权限或耳机不提供通话模式时，请检查系统权限与耳机设置。拔出耳机后重新选择可用设备。支持设备的回声消除／降噪会启用。

Camera2 采集由前台页面管理，最大 480 px、每秒最多一张，JPEG 压缩目标 28 KB、硬上限 32 KB。待发队列超过 8 KB 时跳过视频帧；语音队列上限另设 64 KB。设置的连接信息显示当前流量、待发量和跳帧数。播放确认依据 `AudioTrack` 实际播放头位置；写入缓冲区不等于已播放，中断只报告当前未确认块已播放的毫秒数。

## 首次安装后如何更新

采用与日序相同的 **Java WebView 原生外壳 + 完整网页 ZIP OTA**。沿用日序已有模式，以最少原生依赖交付；此处没有改动日序的代码、签名、域名或更新通道。

首次安装自带完整网页资源。冷启动检查独立 HTTPS 通道 `https://guihualab.cn/liveai/app-updates/latest.json`，只接受 `liveai-stable`，校验完整 ZIP 的 SHA-256 和 `minShellVersion`。下载上限 12 MB，解压上限 32 MB，限制文件数并拒绝路径穿越。完整资源包独立解压后原子切换，不混用新旧网页资源。

保留上一健康版本。新页面通过就绪回调后才标记健康；启动 15 秒未就绪会回退，下次冷启动也会处理未确认版本。失败版本不会循环安装。断网或下载失败时继续使用上一健康版本或 APK 内置资源，不要求重装。

常规界面、交互与网页业务逻辑更新：**彻底关闭 APP，再重新打开**后检查并应用；切回前台不会强制刷新、打断输入。服务端提示词和 API 逻辑发布后由服务器直接生效。新增原生权限、插件、原生依赖或系统能力仍可能需要新 APK；沿用包名、签名并递增版本号，不要求卸载旧版。

保持 `https://guihualab.cn` 的 origin 和 `/liveai/` 路径不变，后续更新保留本 APP 的登录 Cookie、localStorage 历史和草稿。APP 与手机浏览器是独立存储容器，首次安装不会自动取得浏览器里的历史；OTA 也不等于云端同步。用户记录仍仅保存在当前容器，服务器不保存音视频或对话文字。

断网可打开内置/缓存界面；登录验证、实时 AI、图像生成和模型列表需要联网。本版不提供离线 AI。已有本机记录和草稿不会因网页版本切换而删除；新通话记录改为原生加密保存，旧 localStorage 记录仍合并展示。

## 维护与发布

环境：Node 22.12+、JDK 21、Android SDK 36 / Build Tools 36.0.0、Gradle 8.14.3、AGP 8.13.0。原生使用 Android 平台音频／摄像头能力及 OkHttp 4.12.0（纯 JVM，无 ABI 专用库），Robolectric/JUnit 仅为测试依赖。

```bash
npm ci --include=dev
# 仅首次准备本项目独立签名；存在时不替换、不重置。
python3 scripts/prepare-signing.py
npm run build:apk
npm run publish:apk
```

签名材料只放在 Git 外：`/etc/liveai/android-release.p12` 与 `/etc/liveai/android-signing-password`。可通过 `LIVEAI_KEYSTORE`、`LIVEAI_SIGNING_PASSWORD_FILE` 指定其他私有路径。不要输出、提交或打包这些文件；公开的 `android/release.json` 仅包含包名、版本与证书指纹。后续原生更新同步修改 `android/app/build.gradle` 与 `android/release.json` 的版本，不重新生成签名。

构建命令执行网页构建、完整资源打包、Android Release、Lint、原生单元测试、zipalign、正式签名和签名校验，输出 `artifacts/liveai.apk`。发布命令再次检查实际包名、版本、证书及摘要；拒绝降级和同版本换包，保留版本归档与校验文件。安装包不含服务器 API 密钥、密码、Cookie、签名私钥或用户资料。

**网页与 APP 网页资源统一发布命令：**

```bash
npm run deploy:web
```

此命令同时构建网页、运行检查、生成独立 OTA 完整包及清单，跟随同一次原子发布生效。`npm run deploy` 是同一个入口。普通页面变更不再重打 APK。`app-updates` 仅公开受检查的构建文件，`downloads` 仅公开已验证的安装包；其他 API 继续登录保护。IP 下载路径在现有 8182 Caddy 中独立配置，终端等其他路径保留原认证。
